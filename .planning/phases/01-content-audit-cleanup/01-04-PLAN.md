  <action>
Create `scripts/generate-keyword-map.js` that:

1. Reads the existing `seo/keyword-map.json` to preserve manually curated entries (71 service+location pages + hubs + cannibalization rules)
2. Reads `seo/word-count-audit.json` to get the full page list
3. Reads `seo/thin-content-decisions.json` to exclude pages marked "redirect" (already deleted) and "noindex" (not indexed)
4. For each INDEXABLE page that lacks a keyword map entry, derives a primary keyword:

**Derivation rules (in priority order):**
a. If the page's metadata `title` exists, extract the core keyword phrase (strip brand name, location qualifiers like "in Tampa", action words like "Expert Guide to")
b. If the URL slug is descriptive (most are), convert slug to keyword phrase: `commercial-construction-tampa` -> "commercial construction tampa"
c. For article pages with long slugs like `boost-sales-with-effective-...`, extract the core topic: "effective [topic]"

**Output format per entry:**
```json
{
  "url": "/commercial-construction-tampa/",
  "primary_keyword": "commercial construction tampa",
  "source": "existing|derived-title|derived-url",
  "page_type": "service-location|article|hub|location"
}
```

5. Merge new entries with existing ones (existing entries take priority -- never overwrite manually curated keywords)
6. Write the complete map back to `seo/keyword-map.json`, preserving the existing structure but adding new entries

**Page type classification:**
- `service-location`: matches pattern `/{service}-{city}/` (e.g., commercial-construction-tampa)
- `hub`: pages like /services/, /locations/, /insurance-restoration/
- `location`: pages under /locations/{city}/
- `article`: everything else (blog/guide content)

Run the script:
```bash
node scripts/generate-keyword-map.js
```

<task type="auto">
  <name>Task 2: Detect and resolve keyword cannibalization (AUDIT-05)</name>
  <files>
seo/cannibalization-report.json
seo/keyword-map.json
  </files>
  <action>
Write a script (inline or as `scripts/detect-cannibalization.js`) that:

1. Reads `seo/keyword-map.json`
2. Groups pages by primary_keyword (case-insensitive, normalized)
3. Identifies conflicts: any primary_keyword assigned to 2+ pages
4. For each conflict, determines a winner based on:
   - Page type priority: service-location > hub > location > article
   - Word count (from word-count-audit.json): longer content wins among same type
   - URL structure: shorter, cleaner URLs win among same type and similar length

5. For each conflict, assigns resolution:
   - **KEEP**: Winner keeps the keyword
   - **REASSIGN**: Loser gets a more specific/long-tail keyword variant
     - If two pages target "commercial construction tampa", the article might become "commercial construction process tampa" or "guide to commercial construction tampa"
   - **MERGE**: If pages are nearly identical, mark one for redirect (note: redirect execution was in Plan 03 -- here just flag it)

6. Write results to `seo/cannibalization-report.json`:
```json
{
  "generated": "2026-02-15",
  "summary": {
    "total_conflicts": 15,
    "resolved_keep": 15,
    "resolved_reassign": 12,
    "resolved_merge": 3
  },
  "conflicts": [
    {
      "keyword": "commercial construction tampa",
      "pages": [
        {"url": "/commercial-construction-tampa/", "type": "service-location", "wordCount": 1250},
        {"url": "/guide-to-commercial-construction-tampa/", "type": "article", "wordCount": 800}
      ],
      "winner": "/commercial-construction-tampa/",
      "loser_action": "reassign",
      "new_keyword": "commercial construction guide tampa"
    }
  ]
}
```

7. Apply reassignments to `seo/keyword-map.json` -- update the losers' primary_keyword to the new keyword

Run the script, then verify the keyword map has no duplicates:
