<task type="auto">
  <name>Task 1: Build article classification script</name>
  <files>scripts/classify-articles.js</files>
  <action>
    Create `scripts/classify-articles.js` that:

    1. **Reads inputs:**
       - `seo/keyword-map.json` for page types and keywords
       - `lib/constants.ts` SERVICES array for existing silo assignments
       - Scans `app/` directory for all root-level directories that contain a `page.tsx`

    2. **Identifies articles** (pages to move):
       - All root-level `app/[slug]/page.tsx` pages where page_type is "article" in keyword-map
       - EXCLUDE these root-level pages (they are NOT articles, they stay at root):
         - Pages already under a silo: anything in `app/commercial/`, `app/residential/`, `app/insurance/`, `app/services/`, `app/locations/`
         - Service+location pages: anything matching pattern `*-tampa*`, `*-clearwater*`, `*-st-petersburg*`, `*-lakeland*`, `*-sarasota*`, `*-brandon*`, `*-ruskin*`, `*-largo*` (these are money pages, not articles)
         - Structural pages: `contact`, `about`, `team-members`, `privacy`, `terms`, `premium-homepage`, `blog`
         - Hub pages already resolved in 02-01: `commercial-construction`, `custom-homes`, `insurance-restoration`, `disaster-recovery-insurance-restoration`

    3. **Classifies each article into a silo** using this priority chain:
       a. **SERVICES silo match:** If the article's URL contains a service keyword from `lib/constants.ts` that has a silo assignment, use that silo. E.g., articles with "condo-remediation" → commercial (per SERVICES).
       b. **Keyword pattern match:** Apply pattern matching:
          - COMMERCIAL patterns: `commercial`, `contractor`, `construction` (without `custom-home`), `building` (not `home`), `office`, `retail`, `industrial`, `project-management`, `value-engineering`, `leed`, `sustainable`, `pre-construction`, `design-build`, `tilt-up`, `warehouse`, `tenant`, `renovation` (commercial context), `balcony`, `waterproofing`, `historic-restoration`, `concrete`, `steel`, `roofing` (commercial)
          - RESIDENTIAL patterns: `custom-home`, `home-design`, `kitchen`, `bathroom`, `waterfront`, `luxury-home`, `family-home`, `pet-friendly`, `energy-efficient`, `aging-in-place`, `smart-home`, `outdoor-living`, `pool`, `garage`, `master-suite`, `home-renovation`, `residential`
          - INSURANCE patterns: `insurance`, `disaster`, `hurricane`, `storm`, `flood`, `fire-damage`, `water-damage`, `mold`, `claims`, `restoration` (insurance context), `emergency`, `tornado`, `wind-damage`, `smoke-damage`, `public-adjuster`
       c. **Content-based fallback:** For truly ambiguous articles, classify by target audience:
          - Property managers, developers, business owners → commercial
          - Homeowners, families → residential
          - Claims, recovery, damage assessment → insurance

    4. **Outputs `seo/article-classification.json`:**
       ```json
       {
         "generated": "2026-02-15T...",
         "counts": { "commercial": N, "residential": N, "insurance": N, "total": N },
         "articles": [
           {
             "slug": "eco-friendly-commercial-construction-in-tampa",
             "currentPath": "/eco-friendly-commercial-construction-in-tampa/",
             "targetSilo": "commercial",
             "targetPath": "/commercial/guides/eco-friendly-commercial-construction-in-tampa/",
             "classifiedBy": "keyword-pattern",
             "matchedPattern": "commercial"
           }
         ]
       }
       ```

    5. **Prints summary** to console: counts per silo, any articles that fell through to fallback classification, total articles to move.

    **Important edge cases from research:**
    - "disaster recovery" articles about the CLAIMS PROCESS → insurance silo
    - "disaster recovery" articles about CONSTRUCTION WORK → commercial silo
    - "balcony" articles → commercial (per SERVICES constant)
    - "historic restoration" articles → commercial (per SERVICES constant)
    - `insurance-restoration-[city]` pages are service+location pages, NOT articles -- exclude them
  </action>
